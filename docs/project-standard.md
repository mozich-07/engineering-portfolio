# 作品集维护

## 到哪里找项目材料

| 目录 | 内容 |
| --- | --- |
| [projects](../projects/) | 独立项目的说明、源码、图纸和演示材料。先打开项目页，再按文中的链接查看文件。 |
| [collections](../collections/) | 按技术方向整理的项目和短篇实践。同一项目在不同专题出现时，链接指向同一份详细说明。 |
| [docs](../docs/) | 作品集的归档说明和维护记录。 |
| [tools](../tools/) 与 [.github/workflows](../.github/workflows/) | 用于检查作品集的脚本和 GitHub 自动化配置。 |

项目内的 `assets` 保存照片、截图和录像，`src` 保存源码，`models` 保存模型，`results` 保存实验输出。已有软件工程沿用运行所需的目录结构。

## 怎样维护索引

`catalog.json` 保存原有编号与当前落点，多条练习可以共用一个专题。移动文件时同步更新项目页、专题链接和自动检查的工作目录。

提交前运行 `python tools/check_repo.py`。固件改动检查 Uno 编译；工具改动运行对应的构建与测试。涉及实机或模型效果时记录测试条件。团队材料注明个人分工，第三方组件保留许可与署名。
